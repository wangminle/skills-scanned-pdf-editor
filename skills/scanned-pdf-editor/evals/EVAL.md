# scanned-pdf-editor 真实模型评测指南

本文件说明如何对 scanned-pdf-editor 做 **真实模型 with-skill / without-skill 评测**。

> ⚠ 同目录的 `run_evals.py` 是**确定性自检**（关键词 + 合成图 CLI 冒烟），**不运行模型**，
> 不能证明 skill 实际触发或模型遵循。下面的流程才是 skill-creator 规范要求的真实评测。

## 为什么是交互式

skill-creator 规范明确：真实模型评测是**逐 prompt 在新会话里跑一次、人工审阅结果**，
ZCode 不会自动并行运行模型、也没有自动评分文件（无 `grading.json` / benchmark 格式）。
因此本评测必须人工执行，不能脚本化「一键完成」。

## 评测用例

6 个真实用例定义在 `evals.json`，每个含 prompt、期望输出、期望行为（expectations）。
源文件与像素级基准均已归档，可逐像素比对：

| 用例 | 模式 | 源 PDF | 基准 PNG |
| --- | --- | --- | --- |
| 1 | 删除+上移 | `tests/20260720-删除项目/1-原始文件/...委托代理协议 2.pdf` | `2-基准结果/page-1_删除三行并上移.png` |
| 2 | 增加文字 | `tests/20260630-增加项目/1-原始文件/授权委托书_田甜实习律师.pdf` | `2-基准结果/task002_田甜_增加实习律师_最终.png` |
| 3 | 原生供体替换 | `...委托代理协议 2.pdf` + `...协议 3.pdf` | `2-基准结果/page-1_使用PDF3原生结案替换.png` |
| 4 | 替换+删除+上移 | `...委托代理协议 3.pdf` | `2-基准结果/page-1_协议3_胜诉改结案_删除第6第7并上移.png` |
| 5 | 删除+编号替换+上移 | `...专利无效委托协议...3.pdf` | `2-基准结果/page-1_删除指定行_调整编号并上移.png` |

## 运行流程（逐 prompt）

对每个用例，按「without-skill」和「with-skill」各跑一次：

### 1. without-skill 基线（对照组）

- 在**不加载** scanned-pdf-editor 的全新会话里，粘贴用例 prompt。
- 让模型自由尝试（它通常会用 Pillow/cv2 手写脚本、或建议用外部工具）。
- 记录：是否产出可用结果？产出质量？走了哪些弯路（手写脚本、重复读文件、来回试错）？

### 2. with-skill（实验组）

- 在加载了 scanned-pdf-editor 的会话里（或用 `/skill scanned-pdf-editor <prompt>` 强制加载），
  粘贴**同一个** prompt。
- 记录：skill 是否触发？模型是否按 SKILL.md 工作流走（先识别字体/字号、用对应 CLI 子命令、
  留过程记录、跑验证）？产出是否满足 expectations？

### 3. 比对与评分

按用例的 `expectations` 逐条判定，结果填入下方「评测记录」表。
输出 PNG 与基准 PNG 用 `verify_outputs.py` 做像素比对（变化像素、外框、区外变化、空白区深色像素）。

```bash
# 例：用例 1 的输出与基准比对
python3 scripts/verify_outputs.py --config <该用例的 verify_config.json> --reproduce
```

## 评分维度

每个用例按 4 个维度判定（✅ 通过 / ⚠ 部分 / ❌ 失败）：

| 维度 | 判定标准 |
| --- | --- |
| 触发 | with-skill 会话里 skill 被正确加载并执行 |
| 工作流遵循 | 按 SKILL.md 四模式走（识别→编辑→封装→验证），而非手写一次性脚本 |
| 输出正确性 | 输出 PNG 尺寸与源一致、满足 expectations、与基准视觉一致 |
| 效率 | with-skill 比 without-skill 少走弯路（无重复读文件、无废弃脚本） |

## 判定通过门

一轮评测「通过」= 6 个用例的「触发」「正确性」两列均为 ✅。
「工作流」「效率」为观察项，用于指导 SKILL.md 迭代，不阻塞通过。

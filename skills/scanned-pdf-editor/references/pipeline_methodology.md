# 扫描版 PDF 编辑修改 · 方法论参考

本文是 `scanned-pdf-editor` skill 各操作模式和参数背后的"为什么"。
源自两个真实项目的多轮迭代验证，已抽象成通用流程。

---

## 一、两条技术路线

### 路线 A：原生像素迁移

从同页或同系列页找到已有的原生扫描文字/像素块，直接复制到目标位置。

**适用**：删除、移动、替换--这些操作有原生像素可用。

**优势**：天然携带扫描噪点、纸纹、墨色不均、笔画缺损，不需要合成。

**核心操作**：

#### 1. 删除（两种方法）

**方法一：墨迹蒙版 + Telea 修补**

```
框选删除区域 -> 按亮度阈值提取墨迹 -> 5×5 椭圆膨胀 -> 半径 5 的 Telea 修补
```

关键：只在限定矩形内提取墨迹，不整块白色覆盖。Telea 修补利用周围像素填充，
保留纸张色差与颗粒。

为什么膨胀：扫描文字边缘有灰度渐变，阈值提取后蒙版可能有断裂，膨胀连接它们。

**方法二：行间插值填底**

```
框选删除区域 -> 用区域两侧纸张底色逐行插值 -> 纵向平滑(11行窗口) -> 加微噪点(σ≈0.45)
```

适用：需要彻底清除文字与扫描残影的场景（如红线标注区域的完整删除）。

为什么纵向平滑：逐行独立插值会在行间产生色差带，平滑消除接缝。

#### 2. 移动

```
测量行基线差确定移动量 -> 复制原生像素块到目标位置 -> 清理原位置的残留墨迹
```

**移动量必须来自实际行带/基线测量**：

| 项目 | 移动量 | 测量依据 |
|---|---|---|
| 协议 2 | 265 px | 待删三行总高度 |
| 协议 3 | 357 px | 删除两项并保留一行空白后的行差 |
| 重庆协议 | 78 px | 相邻正文行距 |
| 重庆红线版 | 82 px | 红线区域与蓝框区域的行差 |

不能按"约几行"估算。

**移动框边界**：只包正文主栏，不得包含页框、页码、印章、批注。

#### 3. 替换（原生供体）

```
框选供体词块 -> 对比度归一化 -> 4px 羽化 -> 贴入
```

对比度归一化的数学：

```python
donor_contrast = luma(donor_bg) - luma(donor_ink)
target_contrast = luma(target_bg) - luma(target_ink)
contrast_scale = target_contrast / donor_contrast
normalized = target_bg + (donor - donor_bg) * contrast_scale
```

实测对比度倍率（真实项目数据）：

| 场景 | contrast_scale | 说明 |
|---|---|---|
| 协议 2 第 1 处 | 1.0425 | 供体与目标略有差异 |
| 协议 2 第 2 处 | 1.0067 | 几乎一致 |
| 协议 2 第 3 处 | 1.0127 | 几乎一致 |
| 协议 3 | 1.0096 | 几乎一致 |

倍率接近 1.0 说明同系列扫描件之间墨色差异很小。

**不缩放、不锐化、不重新描边**--保留原字的毛边、断笔和色彩噪声。

### 路线 B：字体合成 + 扫描融合

从字体文件渲染干净文字，再叠加扫描噪点/晕染逼近扫描质感。

**适用**：增加文字--没有原生像素可复制。

## 二、字体识别的正确方法

### 为什么不用二值化 IoU

已验证：二值化 IoU（阈值 128）会给出**反向**排名--无衬线字体（微软雅黑 0.549）
反而高于衬线字体（仿宋仅 0.224）。

原因：扫描件墨色深浅不一，二值化阈值很难统一。

### 灰度 NCC + 高度归一化 + 多字聚合

**NCC（归一化互相关）**对线性亮度/对比度不敏感，用满灰度信息，判定稳定。

**高度归一化**：把扫描字和候选字体渲染字都缩放到相同高度（48px），消除字号差异的影响。

**多字聚合**：多个参考字的 NCC 分数求和，降低单字偶然性。

判定标准：
- 总分最高且**衬线明显优于无衬线**才可信
- 已装候选字体少于 2 个时只能判「参考（仅一个已装候选…）」，不得判「确定」
- 均分 ≥ 0.6 且领先第二名 ≥ 0.15×字数 = "确定（明显领先）"
- 否则增加参考字或换更大的字重测

### 常见误区

人们常把所有衬线中文字统称"宋体"，但宋体（SimSun）和仿宋（FangSong）是不同字体。
中文公文正文常为仿宋（GB/T 9704 标准），标题常为小标宋或黑体--但一律以工具实测为准。

## 三、字号识别为什么需要多阈值共识

### 问题

单字墨迹高度 + 松阈值会低估/高估字号 1 档。原因：
- 满框字（如"甜"）墨迹高度偏大
- 扫描虚化晕（>120 阈值）会膨胀墨框
- 单一阈值不稳定

### 解决方案

多暗核阈值(80, 90, 100, 110, 120)各取最优字号，取中位数共识。

实测（task002）：
```
thr  80 -> 32   thr  90 -> 32   thr 100 -> 32   thr 110 -> 32   thr 120 -> 33
推荐字号（中位数共识）: 32   [确定（阈值间共识充分）]   阈值一致: 4/5
```

置信度门：`agree ≥ n−1` 才判"确定"，否则提示增加参考字。

## 四、字重匹配：字体正确不等于效果正确

### 问题现象

字体识别正确（仿宋 NCC 均分 0.890），但合成的"结"字仍显得比原文细、硬、像后来叠加的数字字。

### 像素测量证据

用同一个"结"字对比：

| 指标 | 初次合成 | PDF 3 原生字 |
|---|---:|---:|
| 墨迹外框 | 34×38 | 34×41 |
| `<205` 边缘像素 | 333 | 425 |
| `<180` 笔画像素 | 280 | 301 |
| `<120` 暗核像素 | 99 | 44 |
| `<180` 亮度中值 | 136.6 | 147.9 |

问题诊断：黑色核心集中在较窄轮廓里，中灰扩散层不足（少 22%），形成"细、硬、黑"。

### 原扫描字的视觉粗细 = 四部分

1. 字体原始轮廓和字重
2. 字号及实际墨迹高度
3. 印刷、复印和扫描产生的边缘扩散
4. 灰度分布（深色核心与中灰边缘的比例）

### 解决方案：分开控制三个概念

```text
字体与字号 -> 黑色核心透明度 -> 亚像素字重肩部 -> 随机扫描纹理 -> 极淡外缘晕染
```

**亚像素字重肩部**：

```python
expanded = mask.filter(ImageFilter.MaxFilter(3))
weighted_mask = Image.blend(mask, expanded, STROKE_SHOULDER_BLEND)  # 0.25
```

不是完整增加 1 像素黑边，而是在笔画外侧增加中灰肩部。

> **实现状态**：已合并到 `scan_text_fusion.py` 的 `--stroke-shoulder` 可选参数（默认 0.0=关闭）。
> 替换后备路径（模式 C-2）传 `--stroke-shoulder 0.25` 开启。

**核心透明度缩放**：

```python
alpha = np.power(np.clip(alpha_soft, 0, 1), 0.86) * CORE_ALPHA_SCALE  # 0.875
```

降低大面积死黑核心的比例，让新增面积主要出现在中灰边缘。

> **实现状态**：已合并到 `scan_text_fusion.py` 的 `--core-alpha-scale` 可选参数（默认 0.965=增加文字）。
> 替换后备路径（模式 C-2）传 `--core-alpha-scale 0.875` 开启。

**收敛验证**（与 PDF 3 原生"结"字对比）：

| 指标 | 改进候选 | PDF 3 原生字 |
|---|---:|---:|
| 墨迹宽度 | 34 px | 34 px |
| 墨迹高度 | 39 px | 41 px |
| `<205` 边缘及笔画像素 | 423 | 425 |
| `<120` 暗核像素 | 44 | 44 |
| 中灰像素占比 | 89.60% | 89.65% |

### 关键教训

- **不得把"融合强度"当成"加粗强度"**--提高 fusion-strength 会增加噪点和断笔，不会稳定增加笔画宽度
- **晕染层不能承担笔画增粗**--透明度很低，合成到白背景后仍接近纸白
- **原生供体永远优于合成**--如果存在原生供体，应直接复制

## 五、扫描融合管线（路线 B 详细原理）

### 最终成图只有两步核心渲染

```
源图 -> 扫描融合修复（笔画主体）-> 蓝灰边缘晕染（外缘底噪）-> 最终
```

### 扫描融合修复（render_scan_fusion）

把干净文字处理成有扫描扩散、灰度起伏、轻微断裂、边缘毛刺的笔画。

核心操作（对文字 mask）：
1. 不同强度的高斯模糊（0.34 / 0.72）产生 alpha_soft 和 alpha_halo
2. 边缘带（edge_band）和核心带（core_band）分离处理
3. 随机噪声调制 alpha
4. 模拟边缘脱落（drop < low_drop 时 alpha *= random(0.42, 0.78)）
5. 模拟墨色孔洞（holes）
6. 16 级量化 + 微模糊

### 蓝灰晕染（render_halo）

在笔画外侧加极淡蓝灰扩散。

要点：
- **不给整个字加蓝色**，笔画主体仍是深灰蓝
- **只在外缘**加一圈极淡扩散，且不均匀（带噪点）
- **透明度极低**：平均约 3%~4%，最高约 10%

### 扫描风格分档

| 风格 | fusion 缺省 | 对比档 | 适用 |
|---|---|---|---|
| clean | 0.4 | 0.25, 0.35, 0.5 | 干净扫描（少噪） |
| rough | 1.0 | 0.85, 1.0, 1.15 | 粗糙扫描（定稿强度） |

### 关键洞察：客观指标可能与人眼相反

task002 实测：
- 边缘粗糙度：我的字 2.676 vs scan 2.654（我的字"更平滑"）
- 高频能量：我的字 25692 vs scan 26655（我的字"更平滑"）
- 但人眼看我的字"噪点更多"

原因：fusion 1.0 是为粗糙扫描调的，给干净扫描额外加了 holes/edge-dropout/edge-jitter/ink-speckle，
这些"凭空颗粒"即人眼所感噪点。

**最终以 crop 人眼对比为准，不只信客观数据。**

## 六、颜色取样与暗度匹配

### 取色方法（路线 B）

框选风格相近的既有文字，按亮度逐级收紧阈值（180->165->150->135->120->105），
取最暗一批像素的颜色中位数作为 ink-color。

### 供体归一化（路线 A）

分别取供体和目标的纸白（luma > 235）中位数和墨迹（luma < 180）中位数，
计算对比度倍率后整块映射。

### 暗度验证

| 场景 | 新字暗度 | 参考字暗度 | 评价 |
|---|---|---|---|
| task002 "实" | `<100` 均值 65.3 | 田 61.7 / 甜 62.1 | +2.9 灰阶，可接受 |
| task003 第1处 | donor_ink ≈ target_ink | scale 1.0425 | 对比度接近 |

## 七、视觉判断要点

把修改区域 crop 和邻近原扫描字 crop 并排看，逐项对照：

| 现象 | 含义 | 对症 |
|---|---|---|
| 字形/笔画风格不同 | 字体没对（最严重） | 回字体识别 |
| 轮廓太规整、像矢量字 | 缺扫描不规则性 | 融合强度上调 |
| 偏虚、糊 | 融合过度 | 融合强度下调 |
| 主体偏黑或偏浅 | 颜色没对上 | 重新取样 |
| "浮"在上面、缺底色感 | 缺蓝灰晕染 | 晕染强度上调 |
| 边缘有可见蓝边 | 晕染过度 | 晕染强度下调 |
| 位置偏上/偏下 | 基线没对齐 | position Y 微调 |
| 供体边缘有矩形接缝 | 羽化不足 | 增大 feather |
| 删除区有白色补丁 | Telea 半径太大或区域太空 | 缩小区域或用插值法 |
| 移动后尾部有重影 | 清理区不够 | 扩大 cleanup_boxes |

经验：**原扫描字天然有"不完美的扩散和起伏"**--边缘不锐利、墨色不均匀、偶有断裂。
新增/替换文字要追的就是这种"不完美"，而不是更清晰。

## 八、参数安全范围

| 参数 | 建议范围 | 单步幅度 |
|---|---|---|
| fusion-strength | 0.3~1.2（干净扫描 0.3~0.5） | ±0.05~0.1 |
| halo-strength | 0.7~1.3 | ±0.05~0.1 |
| ink-color（每通道） | 参考值 ±5 | ±2~4 |
| position Y | 已对齐后尽量不动 | ±2px |
| font-size | 参考字高 ±1 | 1 |
| 供体对比度倍率 | 通常 0.95~1.05 | - |
| 羽化宽度 | 3~5 px | 1 |
| 移动量 | 实测行距 | 不估 |
| 墨迹阈值 | 160~246（视扫描质量） | - |
| 修补半径 | 3~7 | - |
| STROKE_SHOULDER_BLEND | 0.20~0.30 | ±0.05 |
| CORE_ALPHA_SCALE | 0.85~0.90 | ±0.01 |

## 九、DPI 基准的选择

| 操作模式 | 推荐 dpi | 原因 |
|---|---|---|
| 删除 / 移动 / 替换 | 300 或内嵌图 | 纯搬像素需高精度定位 |
| 增加文字（融合） | 200 | 融合 alpha 上限约 0.93，200dpi 下采样使整页均匀变浅到融合可达范围 |

**不要混用 dpi 基准**--同一任务全程使用同一 dpi。

200 dpi 的自洽原因：扫描融合的 alpha 上限约 0.93，无法复现极重墨扫描件的暗度。
300 dpi 下"田甜"主体约 33、融合输出最快约 56，永远对不上。200 dpi 下采样把整页
（含"田甜"）均匀变浅到约 62，正好落在融合可达范围内。

## 十、可复现性

- `--seed`（默认 20260701）控制所有噪声。同 seed + 同参数 = 完全一致的输出。
- 路线 A 的操作（删除/移动/替换）是确定性的，不需要 seed（插值填底除外）。
- OpenCV Telea 在不同版本/平台上可能让修补区出现极小的舍入差异；复现检查容差为
  差异不超过 10,000 px、单通道最大差不超过 4、全图 MAE 不超过 0.001。

---

## 十一、局限

- **每份扫描件特性不同**（模糊度、色偏、纸张），定稿参数换一份不会完全适用，必须按
  "参考取样 -> 操作 -> 对照微调"的流程重新收敛一遍。
- **核心难点是视觉判断**，每轮的"加 10%、移 2px"是人机交互的，工具无法替你省掉这一步。
- **路线 B 永远在追"不完美"**--合成字永远不如原生供体自然，这也是优先级链把字体合成放在最后的原因。

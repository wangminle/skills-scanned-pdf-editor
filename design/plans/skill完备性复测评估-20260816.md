# scanned-pdf-editor skill 设计完备性复测评估（20260816）

**复测方式**：由 agent 按 SKILL.md + basic-tests-readme 字面流程独立重跑 `tests/测试任务/` 全部 5 个任务（不复用早前会话结论），记录所有卡点、绕行与文档失效处。结果产物：`tests/results/20260816-0001 ~ 0005/`（各含过程记录.md）与 `tests/results/20260816-对比报告.md`。

**总体结论**：核心能力链（删除/移动/替换/旋转封装/校验防呆）设计完备、实测五任务全部达成且与期望一致；**不完备集中在三处：模式 D 的分辨率死锁、字体体系的注册表覆盖、以及「文字内容定位」环节缺少 OCR 辅助**。另有若干文档-实现不一致与验证表述问题。

## 一、阻断级缺陷（按字面流程会失败）

### ① 模式 D「200dpi 约定」与 package 原生分辨率要求构成死锁 ⭐ 最重要

- 实测：task002（内嵌 2480×3507 ≈300dpi、/Rotate=0）按 readme 字面步骤（pdftoppm 200dpi → 融合 → `package --original-pdf`）在封装步被正确拒绝：`编辑图尺寸 1654×2338 与内嵌图 2480×3507 均不匹配`。
- SKILL.md 自己写明融合 alpha 上限 ≈0.93「无法复现极重墨扫描件暗度，200dpi 下采样自洽」——但 200dpi 成品过不了封装；原生分辨率融合又达不到墨色（task002 原文墨色核心均值 21，融合极限约 39，靠 ink-color 压到 (8,8,12) 才逼近）。
- task001 恰因内嵌≈200dpi 且 /Rotate≠0 侥幸走通，掩盖了该缺陷。
- **建议**：模式 D 增加「封装前检查内嵌图分辨率」步骤；内嵌≠200dpi 时给出两条显式路线：(a) 原生分辨率融合 + ink-color 深化（本复测验证可行）；(b) 新建 PDF 模式（--page-size，放弃 OCR 层）。同时修正 basic-tests-readme task002 的步骤。

### ② pdftoppm 硬依赖、无替代指引

- 本机无 poppler，模式 D 第 1 步（SKILL.md 与 readme 均写死 `pdftoppm`）无法执行；skill 未提供任何替代。本复测用 PyMuPDF `page.get_pixmap(dpi=200)` 等价替代（同为显示朝向）。
- **建议**：SKILL.md 模式 D 第 1 步注明「或 PyMuPDF 渲染」；或提供一个 `render_page.py` 小工具统一入口（顺带固化 dpi/朝向语义）。

### ③ 无 OCR 辅助定位指引，纯目视定位在中文扫描件上不可靠 ⭐

- 实测两次被视觉模型误导：①把任务描述复读成坐标（声称条款 2 在 y1656，实际在 y149，行为完全幻觉）；②(三)/(四) 编号、行序多次自相矛盾。tesseract chi_sim（本机已装）整页 OCR + `locate_content lines` 行带双证据后一次定位成功。
- SKILL.md 定位环节只有像素级行带/字框检测，"确认框内是什么字"隐含依赖目视；`--crop-box` 预览也无法解决内容确认问题。
- **建议**：SKILL.md 定位章节增加「OCR 行映射优先，行带/字框做精确坐标」的双证据流程；requirements/参考文档注明 tesseract（含 chi_sim）为推荐依赖；`locate_content` 可考虑直接集成 `--ocr` 选项输出「行带+文本」。

## 二、字体体系缺口（模式 D 的头号风险，与 20260807 复测结论一致但根因更清楚了）

### ④ 注册表覆盖不全：本机可用字体被报「未安装」

- `~/Library/Fonts/NotoSansSC.ttf`（Google Fonts 常见发行名）不在注册表（只认 NotoSansCJKsc.ttc）；STHeiti Light/Medium.ttc 也不在册。check_fonts 显示 13 个「未安装」造成误导——其中数个本机其实有近似可用。
- **实测收益**：把 NotoSansSC 通过 `--candidates` 纳入后，task001 密度比从 1.17（Hiragino W6）改善到 0.91。

### ⑤ ttc 多字重不可达（注册表与 --candidates 双双不支持索引）

- 注册表把「Songti SC」固定映射 Songti.ttc index 0 = **Black**；Songti SC Light/Regular（对细笔画文书最合适）无法通过注册名使用。
- `--candidates 名称=文件名` 无法表达 ttc 索引：Hiragino W3/W6 候选同分（都渲染了 index 0）为实证。
- 本复测用 fontTools 抽取 Songti SC Light/Regular/STSong 为独立 ttf 绕行；task002 密度比从 1.85（STHeiti Medium）改善到 **1.30（入门禁区间）**。
- **建议**：注册表候选支持 `(文件名, 索引, 字重名)` 三元组；--candidates 语法扩展 `名称=文件名[idx]`；check_fonts 列出 ttc 内全部字重。

### ⑥ 密度门禁结果随分辨率漂移

- 同一字体对：200dpi 下密度比 1.30（通过），原生分辨率下 1.63（拦截）——门禁判据未做分辨率归一化说明，同一文档在不同工作分辨率下结论相反。
- **建议**：identify_font 输出注明测量分辨率；或密度比按笔画面积而非像素占比归一。

### ⑦ check_fonts 安装引导覆盖不了「无 Windows、网络受限」场景

- 本复测 brew 安装 Noto Serif CJK 超时未完成（>40 分钟）。skill 的引导只有「从 Windows 复制」与「brew 开源字体」两条路。实际上 macOS 系统字体里已有 Songti 多字重/STSong/STHeiti 可当近似候选，但注册表看不见（见④⑤）。
- **建议**：check_fonts 增加「列出本机全部可用 CJK 字体（含 ttc 展开）」模式，而不是只对着固定清单打勾。

## 三、验证与测试基建缺口

### ⑧ verify_outputs.py 无基础任务配置样例

- 五个任务没有任何 verify_config；旧 `verify-task003-task004.json` 对应已删除的旧版 PDF，失效。本次验证全部手工 numpy（空白区 dark 计数、保留区 diff、内嵌图一致性、行投影相关）。
- **建议**：为五个基础任务各配一份 verify_config（allowed/blank/preserve/dark 框），纳入 run_checks 可选门禁；把这些手工验证沉淀为脚本。

### ⑨ 「300dpi 回渲与确认 PNG 逐像素一致」表述物理不可达

- 597×839pt @300dpi = 2487.5px ≠ 内嵌 2489px，回渲必有 1px 重采样（task003 实测回渲 diff 9.7% 全部源于此）。真正可靠的表述是：「封装后**内嵌图**与编辑图逐像素一致（本复测五任务全部 diff=0）+ 回渲仅校验朝向/版式」。
- **建议**：修正 SKILL.md 验证表该行；增加「抽取内嵌图比对」为标准验证步骤。

### ⑩ 期望效果对比缺「基线对照」方法

- 期望 PNG 与源图本身存在跨渲染后端基线差（task003 实测未编辑区 7.57%）——不做基线对照直接看全页 diff 必然误判。20260809 报告的 1.78%/6.4% 差异即混入此因素。
- **建议**：对比规程固定为：先测「源 vs 期望」未编辑区基线，再看「成品 vs 期望」编辑区是否≤基线。

## 五、边角发现

- **测试数据瑕疵**：task004 源 PDF 三处「胜诉」的「诉」字均无实体墨迹（仅 9×14px 残点，连通域三处同构）——测试 PDF 是从「结案」原件合成而来且字形渲染缺失。按理论字宽定位会踩空；skill「贴前用局部 crop 目视或 OCR 确认框内文字」的原则在这类数据上是必要防线。
- **locate_content lines 默认 min-ink-ratio 0.01 漏短行**：「实施。」行 ink_ratio 0.015（task005），需降到 0.005 才检出。SKILL.md 测量规程未提示短行降阈值。
- **视觉模型作为「人眼」的可靠性未设防**：SKILL.md 反复要求「以 crop 人眼对比为准」，但 agent 的目视即视觉模型，存在幻觉（本复测实测三次）。建议验证环节默认「OCR 复核 + 像素指标（暗度均值/密度）」双通道，视觉模型只作终审。

## 六、正面确认（设计完备且实测通过的部分）

1. **四种模式的像素质量**：删除不留白斑（interpolate/telea）、移动保原生像素、供体替换对比度归一——task003/004/005 与期望 diff≤0.43%、行投影相关 ≥0.993。
2. **封装防呆**：尺寸不匹配拒绝静默重采样、/Rotate=180 或正方形拒绝 auto、坐标负值/越界/倒置全部显式报错——本次触发过尺寸拒绝（正确）且全部校验无一误报。
3. **旋转闭环**：export-page --as-displayed ↔ package --source-orient displayed 在 /Rotate 270 的 task001 一次通过，回渲 diff=0。
4. **操作编排原则**（先替换后删除、先上后下移动、content-x 整带测量、移动量实测）在 task004（跨页供体）、task005（同页供体→删→移）两个多操作任务中按文档执行无歧义。
5. **质量门禁与降级链路**：identify_font 密度门禁两次按设计阻断；--allow-degraded 显式留痕；回填参数可直贴下一步。
6. **OCR 层保留**：package --original-pdf 在 task002 完整保留原 OCR 文字层。
7. **过程记录规范**可执行，五任务记录齐备且可复盘。

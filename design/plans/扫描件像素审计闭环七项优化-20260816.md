# 扫描件像素审计闭环七项优化（20260816）

## 1. 背景与结论

本次以《20260306-嘉兴启净涂装》三页扫描合同的独立重做为回归样本，评估
`scanned-pdf-editor` 是否能独立交付可证明的像素级编辑结果。

结论：原 Skill 作为扫描件像素编辑工具箱已具备删除、移动和原生供体替换的核心能力；
但原先缺少“正确提取 → 编辑 → 安全回封 → 像素审计”的闭环，严格合同类场景仍需在
Skill 外编写 PyMuPDF/NumPy 脚本。以下七项改造后，关键审计能力已纳入 Skill。

| 环节 | 改造前 | 改造后 |
| --- | --- | --- |
| 删除文字 | Telea 可用，但浅灰残影容易漏检 | 默认 180/220/240 三级残影检查 |
| 移动原生内容 | 能无损搬移，但手动清理框语义易误解 | `auto/add/replace` 显式清理模式 |
| 原生供体拼接 | 能保留原生字形、墨色和扫描质感 | 增加碰撞、字距、基线报告与可选门禁 |
| PDF 封装 | 可替换内嵌图，但假定用户已准备正确 PNG | `extract` 统一提供原生像素基图并做往返验证 |
| 像素验证 | 可查变化外框/哈希，但空白检查过浅 | 多阈值残影、未修改页哈希、MuPDF 回渲门禁 |
| 坐标测量 | 需临时 NumPy 脚本 | `measure_layout.py` 提供四类可归档测量 |
| 允许区审计 | 需手工写像素代码 | 封装阶段自动拒绝允许区外变化 |

## 2. 回归样本与原始证据

样本为三页扫描 PDF。业务编辑目标是删除第二条律师费支付说明中的一段文字，并将其后的
金额行上移到冒号后，同时保持其他页面和页面其他区域不变。

独立测量得到：

- 金额行墨迹顶端：2662px；目标槽位墨迹顶端：2388px；实际移动量：274px；
- 冒号止点：1520px；“人”字起点：1529px；实际字距：9px；
- 第一版原位置残影：亮度 `<180` 为 32 像素、`<220` 为 211 像素、`<240` 为 2946 像素；
- 独立终版同一区域在 `<220`、`<240` 下均为 0。

这些数据说明：仅观察深色文字或仅看全页视觉效果，无法证明浅色残影、字距碰撞和未修改页
没有被误改。

## 3. 七项问题、根因与落地方案

### 3.1 缺少安全的 PDF 原始扫描图提取入口

**问题与根因**：旧流程只有 `package`，没有对称的 `extract`。用户容易用 PIL 解码 PDF
内嵌 JPEG 后再封装；视觉上虽接近，但 JPEG、PNG 与渲染器的色彩解码链不同，可能造成全页
差异。旧封装入口也无法证明输入 PNG 与原 PDF 显示结果一致。

**落地**：

- 新增 `scan_edit_ops.py extract`；`export-page` 保留为兼容别名；
- 使用 `fitz.Pixmap(document, xref)` 提取覆盖面积最大的整页扫描图，得到原生 RGB 像素；
- 提取后强制检查 PNG 回读像素、回封后的内嵌图像素、300dpi 回渲、未修改页哈希；任一失败则
  删除刚导出的 PNG，拒绝其成为编辑基图；
- 保留 `/Rotate` 的 displayed/embedded 朝向链，要求回封时显式或可靠推断朝向。

**关键取舍**：实测 PDFium 对“原 JPEG XObject”和“替换后的相同 RGB PNG XObject”会产生全页
色彩差异（本样本约 1,213,792 个变化像素，最大通道差 57）；MuPDF 对两者回渲 diff=0。
因此像素闭环审计统一使用与 `fitz.Pixmap` 同链的 MuPDF，而 PDFium 仍可作为一般兼容渲染器。

**实现位置**：`scan_edit_utils.py` 的 `extract_embedded_page_image`、
`render_pdf_page_mupdf`，以及 `scan_edit_ops.py` 的 `extract` 子命令。

### 3.2 空白残留检查阈值固定为 180

**问题与根因**：旧 `blank_box` 固定使用 `<180`，只能识别较深残留；扫描文字的淡边、修补后的
浅灰影通常落在 180–240 区间，因此第一版“验证通过”但肉眼仍可见残影。

**落地**：

- CLI `verify` 默认 `--blank-thresholds 180,220,240`；
- `verify_outputs.py` 增加 `blank_thresholds` 与 `blank_dark_limits`，支持每级阈值独立上限；
- 兼容旧 `blank_dark_limit` 与旧单阈值 CLI 参数，但严格交付不应退回单阈值。

**实现位置**：`scan_edit_ops.py` 的 `parse_thresholds`、`cmd_verify`，以及
`verify_outputs.py` 的 `_blank_check_config`。

### 3.3 没有行距、字框、字距与移动量测量工具

**问题与根因**：旧 Skill 要求“移动量必须实测”，但没有可复用测量入口，只能临时写 NumPy
行投影和墨迹边界代码。275px 与 274px 的偏差、冒号后的贴字距离等问题因此难以提前量化。

**落地**：新增 `measure_layout.py`，全部命令输出 JSON，便于直接写入过程记录：

| 子命令 | 产出 |
| --- | --- |
| `lines` | 行带顶底、行高、行距、墨迹率 |
| `ink-bbox` | 区域墨迹最小外接框及像素数 |
| `gap` | 两框碰撞、水平/最近距离、垂直重叠、基线/中心差 |
| `shift` | 源/目标墨迹框及顶端、基线、中心移动量 |

测量默认阈值为 220；用户可按扫描质量调整。

### 3.4 没有文字碰撞、字距和基线验证

**问题与根因**：旧 `replace` 仅报告对比度倍率与变化外框，无法回答供体是否压到冒号、是否紧贴
下一字、是否偏离同一行的基线。羽化贴片与未清净的原字相交也只能靠人工观察。

**落地**：

- 新增 `analyze_replace_placement`，以贴入前后的像素差与暗墨迹掩模计算供体墨迹框、碰撞像素、
  最近欧氏距离、左右字距、基线偏差及中心偏差；
- `replace` 输出 `placement_analysis` JSON；
- 提供 `--fail-on-collision`、`--min-gap`、`--max-baseline-deviation`，可将报告升级为
  交付门禁；`--analysis-threshold` 默认 220。

### 3.5 多页“未修改”验证不完整

**问题与根因**：旧验证只检查页数和目标页。第 2、3 页“完全未改动”的结论必须在 Skill 外逐页
提取图像并比 SHA-256，无法自动保证替换一个共享 XObject 时不会连带影响其他页面。

**落地**：

- 新增 `embedded_page_image_hash`：对整页扫描图 RGB 原生像素（包含尺寸）计算 SHA-256；
- 新增 `compare_unmodified_page_hashes`：比较除目标页外的全部页面；
- `package --original-pdf` 与 `verify_outputs.py` 默认都执行该检查。

### 3.6 `move` 的手动清理框语义不明确

**问题与根因**：旧 `cleanup_boxes` 一旦提供就替代自动尾部清理框，而名称和常见直觉容易被理解成
“额外追加”。用户只补充一个特殊区域时，原自动尾部未清理，便会留下原位墨迹。

**落地**：`move` 新增 `--cleanup-mode`：

| 模式 | 行为 |
| --- | --- |
| `auto` | 仅自动尾部清理框；不能同时传手动框 |
| `add` | 自动尾部框加手动框 |
| `replace` | 仅手动框；未传手动框即报错 |

这使“自动、追加、替代”成为显式且可测试的选择。

### 3.7 封装后缺少强制的允许区外像素门禁

**问题与根因**：仅比较编辑 PNG 的差异外框无法覆盖 PDF 封装后的坐标变换、`/Rotate`、非等比
XObject 放置和颜色解码。若封装导致页面其他区域变化，旧流程仍可能交付成品。

**落地**：

- `package --original-pdf` 默认要求 `--audit-allowed-boxes`（显示朝向提取图坐标）；
- 先生成候选临时 PDF，不覆盖用户输出；
- 用黑底和白框替换页图，生成两份掩模 PDF，经同一 XObject 放置和 `/Rotate` 用 MuPDF 300dpi
  双回渲，精确得到回渲允许像素掩模；
- 对原件与候选 PDF 的 MuPDF 回渲做差分；允许区外变化不为 0 即删除候选并失败；
- 仅当“内嵌图回读 diff=0、未修改页哈希一致、区外变化=0”都通过时，候选才原子替换交付文件。

这种掩模映射避免了简单按宽高比例缩放允许框在旋转页上发生错位的问题。

## 5. 交付流程（改造后）

1. 用 `extract` 导出原生像素，默认往返检查必须通过；
2. 用 OCR + `locate_content` 定位，再用 `measure_layout` 记录行带、字框、字距、移动量；
3. 执行 `remove` / `move` / `replace`；移动时显式指定清理模式，替换时审查
   `placement_analysis`；
4. 对空白区运行 180/220/240 三级残影验证；
5. 使用 `package --original-pdf --audit-allowed-boxes ...` 回封；
6. 将过程记录、测量 JSON、清理蒙版、供体、局部对比、最终 PDF 及验证输出归档。

## 6. 当前边界与后续建议

本轮把严格像素审计纳入了工具链，但以下边界仍需明确：

- 该工具面向“每页有可识别整页扫描图”的扫描 PDF；纯矢量页、多个同等覆盖背景图或没有内嵌图的
  PDF 会安全报错，需要另行处理；
- 允许区必须由操作者按编辑意图声明；工具可证明区外不变，不能替操作者判断声明框是否足够合理；
- `verify_outputs.py` 已默认使用 MuPDF，以避免 JPEG/PNG 容器差异；若为了兼容旧基准显式指定
  PDFium，应先测量未编辑基线，不能把容器色彩差异误判为编辑差异；
- 字体合成路线仍受本机可用字体与扫描质量影响，原生供体仍是替换文字的优先方案。

### 1.2 工作流程（SVG 六步法）

原始项目总结为 **6 步 + 3 个决策门**：

```
①准备源图 -> ②识别字体 -> ③定位+字号 -> ④取样参考色 -> ⑤融合加字 -> ⑥迭代微调
              ↓             ↓                      ↓
          字体确定?       字号确定?           噪点/质感匹配?
```

右侧"过程留痕"证据链：`NCC排名.txt` -> `字形对比.png` -> `clean校验.png` -> `ink色阶.png`

### 1.3 三次关键转折（MD 文档记录）

1. **字体接续错误**：等线 -> 仿宋。最初按"口头字体名"使用等线，NCC 排名揭示真正字体是仿宋（0.816，领先第二名 0.300）
2. **字号手动 +1**：31 -> 32。单字符识别给出 31，视觉判断偏小，+1 后 identify_size.py 确认 32（4/5 共识"确定"）
3. **干净扫描的噪声类型**：fusion 从 1.0 -> 0.5 -> 0.35。原始扫描很干净，过强融合反而显假；"客观噪声指标可能与人眼相反"

### 1.6 核心思路

1. **NCC 而非 IoU**：扫描件有锯齿/模糊，IoU 对噪声太敏感，NCC 关注形状相似性
2. **密度对比（实心 vs 实心）**：不比较渲染字与扫描字的密度（一个有锯齿一个没有），而是比较渲染字与渲染字、扫描字与扫描字
3. **200dpi 自洽**：300dpi 扫描文字太暗（~33），fusion alpha 上限 ~0.93 无法复现；200dpi 降采样后整体变亮至 ~62，落入 fusion 可达范围
4. **干净扫描 fusion 0.3~0.5**：干净扫描噪声少，过强融合显假
5. **不信任口头字体名**：用户说"宋体"但实际是"仿宋"，以 NCC 数据为准

### 2.2 环境对比

| 维度 | 原始项目 | 当前测试 |
|------|----------|----------|
| 平台 | Windows 11 | macOS |
| 仿宋字体 | ✅ 已安装 (simfang.ttf) | ❌ 未安装 |
| 字体识别结果 | 仿宋 NCC 0.816 "确定" | Songti SC NCC 0.355 "存疑" |
| 密度比 | ~1.0x（同字体） | 2.11x ⚠️（字体替换导致） |

**这是当前最大的差距——不是代码问题，是环境问题。** 仿宋是中文公文标准字体（GB/T 9704），macOS 默认不带。Songti SC 虽然同为宋体类，但笔画粗细差异巨大（密度比 2.11x），导致：

- NCC 得分低（0.355 vs 0.816）
- 渲染文字过粗
- 融合后墨色偏深

> **已实现的解决方案**：新增 `check_fonts.py`（DEV-007）提供字体环境检查与安装引导，支持从挂载的 Windows 分区自动复制字体文件。

### 2.3 参数对比

| 参数 | 原始 (task002) | 当前 (task002) | 差异原因 |
|------|----------------|----------------|----------|
| 字体 | 仿宋 | Songti SC | 仿宋未安装 |
| 字号 | 32 | 28 | 字体不同->笔画宽度不同->阈值分组不同 |
| 墨色 | (24, 25, 29) | (60, 60, 62) | 渲染 DPI/字体不同->扫描基线不同 |
| 位置 | (617, 554) | (619, 552) | align_text.py 自动对齐 vs 手动 |
| fusion | 0.35 | 0.5 | 原始迭代降低；当前用默认 |
| halo | 0.5 | 1.0 | 原始迭代降低；当前用默认 |

#### 参数差异分析

**字号 32 vs 28**：字体替换是根因。仿宋笔画细，32px 才能匹配扫描件；Songti SC 笔画粗，28px 的笔画宽度才接近。但即使字号调小了，密度比仍然 2.11x，说明笔画粗细的绝对值仍不匹配。

**墨色 (24,25,29) vs (60,60,62)**：两个值都是在各自环境中 sweep 出来的、匹配各自扫描基线的最优值。原始扫描基线 ~62（200dpi），当前扫描基线 ~71。值不同但逻辑一致——都是"比扫描基线略深一点"。

**fusion 0.35 vs 0.5 / halo 0.5 vs 1.0**：这是**流程差异**，不是代码差异。原始项目经历了用户指导的 3 轮迭代（1.0->0.5->0.35），发现干净扫描需要降低融合强度。当前测试用的是默认值 0.5/1.0，没有做这步迭代。

### 2.6 仍存在的差距与改进方向

#### 差距 1：仿宋字体未安装（环境，非代码）

**影响**：NCC 0.355 "存疑"，密度比 2.11x，字号/墨色全部偏移。这是当前所有参数差异的根因。

**建议**：在 macOS 上安装 simfang.ttf（`~/Library/Fonts/`）。当前 `font_registry.py` 已经收录该目录（BUG-044 修复时加入），`check_fonts.py`（DEV-007）提供安装引导，安装后即可被识别。安装后重跑 task002，预计 NCC 可恢复到 0.8+，字号回到 32 附近。

#### 差距 2：缺少"干净扫描 fusion 迭代"指引（流程，非代码）

**影响**：当前默认 fusion=0.5/halo=1.0 对干净扫描偏强。

**建议**：在 `SKILL.md` 或 `pipeline_methodology.md` 中增加"干净扫描判定 + fusion 降档建议"的指引。原始项目的经验是：扫描件越干净，fusion 越低（0.3~0.5），halo 也相应降低（0.3~0.5）。

#### 差距 3：字号因字体替换而偏移（间接，由差距 1 引起）

**影响**：当前识别 28px 而非 32px。这是因为 Songti SC 笔画更粗，阈值分组给出更小的字号。安装仿宋后此问题应自动消失。

#### 差距 4：密度比警告已触发但无自动调参

**影响**：当前版本能检测到密度比 2.11x 并发出警告，但没有自动调整字号或建议替代字体的能力。

**建议**：当密度比 >1.5 时，可在 `identify_font.py` 输出中增加"建议安装 [字体名] 以获得更匹配的效果"的提示。当前已有 uninstalled font hints 机制和 `check_fonts.py` 安装引导，可以复用。

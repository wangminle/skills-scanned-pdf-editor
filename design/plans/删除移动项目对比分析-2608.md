### 1.4 关键经验教训（流程总结记录）

1. **行内局部删除不可扩展为整行**：task007 首轮用大矩形覆盖三行段落，误删了第一行未画红线的内容（120,178 像素被误改）。修正后拆为三个独立矩形，误改像素降为 0。
2. **编号替换用原生供体**：task006 把行首「，则」替换为「2、」时，从同页第二条款复制原生「2、」而非重新选字体——天然继承字体、字号、笔画粗细和扫描颗粒。
3. **视觉对齐需要微调**：供体「2、」初始位置与该行中线偏移，经两轮调整（4px + 3px = 累计下移 7px）才对齐。
4. **验证须双向**：不只检查「该删的是否删掉」，还要检查「没画线的是否完整保留」——建立了独立的 `unchanged_box` 断言。

## 二、算法级逐函数对比

### 2.1 删除：interpolate 行间插值填底

#### 手动版 `blank_regions()`（task007）

```python
# 采样：左右各 45px
left_sample  = image[top:bottom, left-45 : left]
right_sample = image[top:bottom, right  : right+45]
samples = concatenate([left_sample, right_sample])

# 纸白中值：亮度 >238 的像素
for row in samples:
    paper = row[row_gray > 238]
    row_colors.append(median(paper))

# 纵向平滑：11 行均值（edge padding）
smoothed = [padded[i:i+11].mean() for i in range(height)]

# 微噪点：sigma=0.45, seed=20260804
noise = rng.normal(0, 0.45)
result = clip(fill + noise, 0, 255)
```

#### Skill 版 `remove_regions_interpolate()`

```python
# 采样：同样左右各 45px（sample_width 参数）
# 纸白中值：同样亮度 >238
# 纵向平滑：同样 11 行均值（edge padding）
# 微噪点：同样 sigma=0.45, seed=20260805

# 额外健壮性处理（手动版没有）：
# · 框裁剪到图像边界内（BUG-022）
# · 整页宽框退化为上下邻域采样
# · 采样行数 ≠ 目标高度时 cv2.resize 线性插值补齐（BUG-017）
# · 全暗采样区退化为单行中值时直接复制
```

#### 结论

**核心算法完全相同**——左右 45px 采样、纸白阈值 >238、行中值、11 行纵向平滑、sigma=0.45 微噪点。Skill 版增加了 4 层退化保护（边界裁剪、上下回退、行数补齐、单行退化），是手动版的健壮化泛化。

### 2.2 删除：Telea 墨迹修补

#### 手动版（task006 `erase_comma_and_ze`）

```python
gray = cv2.cvtColor(image, cv2.COLOR_RGB2GRAY)
ink_mask = where(gray < 235 & region > 0, 255, 0)
ink_mask = cv2.dilate(ink_mask, ellipse(5,5))
repaired = cv2.inpaint(image, ink_mask, 5, cv2.INPAINT_TELEA)
```

#### Skill 版 `remove_regions_telea()`

```python
# 完全相同的流程：
# 1. 灰度阈值提取墨迹（ink_threshold 参数，默认 180）
# 2. 椭圆膨胀（dilation 参数，默认 5）
# 3. Telea 修补（inpaint_radius 参数，默认 5）
# 额外：mask_mode 可选 "ink"（仅墨迹）或 "full"（整矩形）
```

#### 结论

**完全一致**。Skill 额外提供 `--mask-mode full` 选项（整矩形交给 Telea），对应原始项目 `replace_with_donor_jiean.py` 的清理方式。

### 2.3 移动：整块复制 + 清理

#### 手动版 task006 `move_first_section_up()`

#### Skill 版

#### 结论

两种移动策略均已覆盖。task006 的「先贴后清理尾部」对应 `move`；task007 的「先 interpolate 清空源区，再粘贴」对应 `compound`。

### 2.4 原生供体替换

#### 手动版 `paste_native_number()`

```python

# 纯底色偏移归一化

target_bg = median(target[luma > 245])

```

#### Skill 版 `replace --normalize-mode offset`

```python
# 完全相同的数学：
# offset 归一化 = donor + (target_bg - donor_bg)
# 4px 羽化 = feather_mask(w, h, edge=4)
# 额外：--normalize-mode contrast（对比度缩放）作为默认选项
```

#### 结论

**算法完全一致**。手动版只用了 offset 模式，Skill 额外提供 contrast 模式（对比度缩放归一化）。

## 三、任务策略对比

### 3.1 操作步骤映射

原始两步法拆解为原子操作后，与 Skill 命令的映射关系：

| 手动操作 | 原子操作 | Skill 等价命令 |
|---------|---------|---------------|
| task006: 删除第一行整行 | （被 task003 的删除段一覆盖） | `remove --boxes "410,170,2065,218" --method interpolate` |
| task006: 清理「，则」墨迹 | Telea 小面积清理 | `remove --boxes "300,248,395,298" --method telea --ink-threshold 235` |
| task006: 替换「，则」→「2、」 | 原生供体替换 | `replace --donor-source page.png --donor-box "378,1328,427,1378" --destination 340,248 --normalize-mode offset --feather 4` |
| task006: 整块上移 78px | move + cleanup | `move --content-x "250,2250" --source-y "230,1135" --shift-y 78 --cleanup-boxes "250,1057,2250,1135"` |
| task007: 删除「若国」+ 第三行 + 「费用。」 | interpolate 删除 | `remove --boxes "1985,160,2090,235" "250,245,2260,335" "250,330,500,420" --method interpolate` |
| task007: 蓝框上移 82px | compound（先清后贴） | `compound --content-x "340,2220" --source-y "395,885" --shift-y 82 --clear-boxes "340,395,2220,885" "1985,160,2090,235" "250,245,2260,335" "250,330,500,420"` |
| PyMuPDF 替换内嵌图 | package | `package --source final.png --original-pdf source.pdf --page-index 0` |

### 3.2 策略差异

| 维度 | 手动两步法 | Skill task003 单步法 |
|------|-----------|---------------------|
| **编号处理** | 把「2：」改为「2、」（删整行后重编号） | 保留「2：」，把保留文字上移合并为「2：甲方需在收到…」 |
| **移动粒度** | task006 把 y=230-1135 整块上移（粗粒度） | 分 3 次精细移动：保留文字 78px + Block1 158px + Block2 79px |
| **(四) 条款** | 不移动 | 上移 1 行（79px） |
| **处理次数** | 2 次脚本（顺序执行） | 1 次工作流（5 步串行） |
| **坐标来源** | 硬编码在脚本中 | CLI 参数 + 像素行检测推导 |
| **行距取值** | task006=78px, task007=82px | 统一 79px（段落平均行距） |

### 3.3 「2：」vs「2、」的设计选择

手动版选择把编号从「2：」改为「2、」：
- 原因：task006 删除了第一行整行（含「2：」），需要在第二行行首重新编号
- 方法：从同页第二条款第 2 项复制原生「2、」供体

Skill 版选择保留「2：」：
- 原因：只删除「如依据…则」段，保留了行首的「2：」
- 方法：把第二行保留文字上移一行，自然合并为「2：甲方需在收到…」
- 优势：无需供体替换，更忠实于原文编号格式

如果用户需要改为「2、」，Skill 可通过 `replace` 命令完成同页原生供体替换——能力已具备。

## 六、结论与建议

### 6.1 核心结论

**当前 Skill 完全覆盖原始手动脚本的全部能力**。删除（interpolate + Telea）、移动（move + compound）、供体替换（replace）、PDF 封装（package）、验证（verify_outputs）五大操作的算法实现与手动版一致或更优。

### 6.2 Skill 的改进

1. **通用 CLI 参数化**——坐标不写死，一份脚本处理任意扫描件
2. **一次工作流**——5 步串行完成（vs 手动 2 次脚本 + 中间 PDF）
3. **健壮性**——越界/倒置/负坐标/NaN/空采样全报错，不会静默错位
4. **模式 D 补全**——字体识别 + 融合加字能力，覆盖手动版未涉及的文字增补场景
5. **文档化**——SKILL.md 工作流指引 + 参数安全范围表 + 方法论参考

### 6.3 可改进方向

1. **行距自动测量**：目前需手动测量行距确定 shift-y，可考虑增加 CLI 工具自动检测相邻文本行的中心距
2. **compound 多移动**：当前 `compound` 只支持一次移动 + 多次清除，如需一次完成多次独立移动（如 task003 的 3 次 move），仍需分步执行
3. **渲染后端统一**：pypdfium2 与 PyMuPDF 回渲存在最多 4 灰度级差异，建议在验证配置中明确标注使用的渲染后端
